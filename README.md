# PBZ-sigpatch

按签名定位的二进制补丁骨架。核心只有一句话：**校验不过就整体拒绝，一个字节都不写。**

先用一句话说清楚边界，免得点进来的人误会：**这个仓库不含任何针对具体游戏或具体程序的补丁数据。** 没有特征码、没有目标偏移、没有现成的可执行补丁。它只是给"我要改某个二进制里的一段字节"这件事提供一套不会静默改错的骨架。

`PBZ` 是从我自己的项目中带出来的名字，项目本身用不到这个仓库里的任何东西，仓库里也不含那个项目的任何东西。

## 它解决什么问题

写死 RVA 的补丁脚本有个毛病：被补丁的程序一升级，偏移就全偏了。脚本还是照常跑，还是报「成功」——因为它验的是同一个错地址。

这个工具换个做法。你给一段特征码，它去目标里找。找到且只找到一处，才动手；一处都找不到、或者找到好几处，直接停下来。中间没有任何"取第一个"的余地。

## 四条规则

补丁描述就三项：签名、偏移、替换字节。判定按这四条来，任何一条不过，整个操作失败，目标文件保持原样。

1. **签名必须唯一。** 出现 0 次或多次都算失败。工具不会替你选一个"最像"的位置。
2. **给了 `expect` 就必须逐字节吻合。** 这是用来确认"当前还是旧版本"的。没有这一步，签名刚好撞上别的构建你也发现不了。
3. **签名只能当上下文，不许覆盖自己要改的区间。** `at` 必须大于等于签名长度。原因下面单说。
4. **多条补丁的覆盖范围不许重叠。** 重叠往往意味着两条签名定位到了同一块地方，这多半是签名写错了。

### 第 3 条为什么单独拎出来

很容易顺手把 `e8 xx xx xx xx` 整条指令写进签名，`at` 指向 `e8`。看起来天经地义，其实是个坑：

打完补丁，`e8` 后面那四个字节变了，**签名就不存在了**。这时候 `verify` 会报「连特征码都找不到」，`apply` 也没法判断是不是已经打过了——每次跑都当第一次处理。

正确写法是签名取补丁点**左边**的一段字节，`at` 指向它后面：

```
... 48 83 ec 28 48 8b c8 4c 8d 4c 24 | e8 aa bb cc dd ...
    └────────── 签名 ─────────────────┘ └── 要改的 ──┘
                                        ↑
                                       at = 签名长度
```

这样签名在补丁前后都在，`verify` 才有东西可查，`apply` 也才能判断"已经是补丁后状态，跳过"。

## 用法

安装：

```
pip install -e .
```

补丁描述是一个 JSON 文件，示例在 `examples/spec.example.json`：

```json
{
  "target": "demo.dll",
  "patches": [
    {
      "label": "把 call 的目标换成新地址",
      "signature": "4883ec28488bc84c8d4c24",
      "at": 11,
      "expect": "e8aabbccdd",
      "replacement": "e811223344"
    }
  ]
}
```

`target` 支持相对路径，相对于 JSON 文件所在目录。

四个子命令：

| 命令 | 干什么 |
|---|---|
| `sigpatch find spec.json` | 只报告命中位置和 RVA，不改文件 |
| `sigpatch apply spec.json` | 校验全部通过才写盘，写前自动留 `.orig-backup` |
| `sigpatch apply spec.json --dry-run` | 报告将要改哪些位置，不写盘 |
| `sigpatch verify spec.json` | 核对目标是否已处于补丁后状态 |
| `sigpatch restore demo.dll --yes` | 从 `.orig-backup` 还原 |

返回码：成功 0，校验失败 1，用法错误 2。能直接接到批处理或 CI 里。

## 写的时候留意的几件事

**只支持等长替换。** 替换字节必须和 `expect` 一样长。加长或缩短会挪动后面所有的偏移、破坏节区表，那是另一类工具的事。

**写盘是原子的。** 先写同目录的临时文件、`fsync`、再 `os.replace`。写到一半断电不会留半个文件。

**备份只留一次。** `demo.dll.orig-backup` 第一次 `apply` 时生成，之后不再覆盖。否则第二次 `apply` 会把原件换成打过补丁的版本，`restore` 就废了。

**`apply` 是幂等的。** 已经是补丁后状态的那几条会被跳过。全都不用改时不写盘。

**校验失败时输入数据不被修改。** `apply_patches()` 拿到的字节序列一个字节都不会动，它返回一个新对象。这条有测试盯着。

## 代码结构

```
sigpatch/
  pe.py       PE 头解析，只管 RVA 与文件偏移互换
  patch.py    签名定位、四条规则、apply_patches
  fsutil.py   原子写入、一次性备份
  cli.py      命令行
tests/
  pebuilder.py       现场合成假 PE
  test_sigpatch.py   32 个用例
```

`pe.py` 只解析到节区表为止，不碰导入表、不反汇编。需要更多信息的地方，接 Capstone 或 pefile 比在这里加代码合适。

## 测试

```
python -m unittest discover -s tests -t .
```

不依赖 pytest，也不读任何真实二进制——所有样本在 `tests/pebuilder.py` 里现场合成。
